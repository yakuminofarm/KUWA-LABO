# アプリ版 (iOS / Android) の作り方

くわらぼは Web アプリとして作ってあり、それをそのまま Capacitor で包んで
iOS / Android アプリにする。画面や記録の仕組みは1つのままで、
出し先だけが2つに増える形。

## 2つの出し先のちがい

|  | ブラウザ版 (Vercel) | アプリ版 (iOS/Android) |
|---|---|---|
| 中身 | サーバあり | 端末に置いた静的ファイル |
| ニュース | 自分の `/api/news` | 公開中の配信を絶対URLで見にいく |
| Service Worker | 使う (オフライン用) | 使わない (最初から端末内にある) |
| 「テスト」表示 | 本番以外で出る | 出ない (本番あつかい) |

切り替えは環境変数 `NEXT_PUBLIC_KUWA_TARGET=native` の1つだけ。
`next.config.ts` と `src/lib/env.ts` が同じ値を見ている。

### なぜ `/api/news` はアプリ版に入らないのか

サーバがないと動かない口なので、静的な書き出しができずビルドが落ちる。
そこでファイル名を `route.web.ts` にして、ブラウザ版のときだけ
`pageExtensions` で拾うようにしてある。アプリ版は既定の拡張子のままなので
`route.web` は口として認識されず、自然に外れる。

アプリ版のニュースは公開中の `https://kuwa-labo.vercel.app/api/news` を
見にいく。別ドメインになるので、この口には CORS の許可を付けてある
(返すのは公開の見出しだけで、誰の記録も含まない)。
取れなければホームは雑学の一言に切り替わるだけで、記録の読み書きには影響しない。

別の場所に置いた口を使いたいときは `NEXT_PUBLIC_KUWA_API_ORIGIN` で変えられる。

## Mac 側の下ごしらえ (最初の1回)

```sh
# Xcode を App Store から入れる (15GB ほど。いちばん時間がかかる)
xcode-select --install
sudo xcodebuild -license accept

# Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Node と CocoaPods (iOS のビルドに要る) と Android Studio
brew install node cocoapods
brew install --cask android-studio

# くわらぼを手元に
git clone https://github.com/yakuminofarm/kuwa-labo
cd kuwa-labo
npm ci
```

## 土台を作る (最初の1回)

`ios/` と `android/` は Mac の上で作る。中に Xcode / Android Studio の
プロジェクトが入るので、作った環境でしか正しく組み上がらない。

```sh
npm run build:native      # out-native/ に静的な一式が出る
npx cap add ios
npx cap add android
npm run assets:native     # アイコン・起動画面を assets/logo.png から作る
```

最後の `assets:native` を忘れると、`cap add` が Xcode の初期テンプレート
アイコン (青い X 印) のまま残ってしまう。ホーム画面に置いたときに
くわらぼのアイコンではなく Xcode 既定のアイコンが出る場合はこれが原因。

素材は `assets/logo.png` (背景を透過したクワガタ+二重螺旋) に入れてある。
`public/icon-512.png` (アプリの地色 `#eddcbb` で塗られた版) から背景色を
抜いて作ったもの。差し替えたいときはこのファイルを置き換えてから
`assets:native` をもう一度実行する。

## ふだんの流れ

画面を直したあとは、これだけで端末に反映できる。

```sh
npm run ios       # ビルド → 同期 → Xcode が開く
npm run android   # ビルド → 同期 → Android Studio が開く
```

内訳:

| コマンド | すること |
|---|---|
| `npm run build:native` | アプリ用に静的な一式を `out-native/` に書き出す |
| `npm run sync:native` | 上に加えて、iOS/Android のプロジェクトへ配る |
| `npm run ios` / `npm run android` | 上に加えて、Xcode / Android Studio を開く |

### 日付を選ぶ欄を日本語にする

日付の欄 (`<input type="date">`) をタップすると出てくる画面は iOS が用意する
もので、Web 側からは言葉を変えられない。iOS は**アプリが対応している言語**を見て
決めるが、Capacitor が作る `Info.plist` は `CFBundleDevelopmentRegion = en` で
`CFBundleLocalizations` を持たない。これだと英語専用のアプリと見なされ、
端末を日本語にしていても月の名前が `September` のまま出る。

`ios/` は Git に入れていないので手で直すと作り直したときに消える。
そこで `npm run sync:native` のたびに `scripts/patch-native-ios.mjs` が
当て直す (何度走らせても同じ結果になる)。同じ script でカメラの使い道
(`NSCameraUsageDescription`) も当てている。

実機に入れるところから先 (署名・証明書・ストアへの申請) は
Xcode と Android Studio の画面での作業になる。

`ios/` `android/` は Git に含めていないので、消して作り直したときは
「土台を作る」を最初からやり直す (`assets:native` も忘れずに)。

### package-lock.json を手で直すときは並び順に気をつける

npm はこのファイルの項目を `localeCompare` の順に並べる。手で項目を足して
位置がずれていると、**`npm install` のたびに npm が並べ直す** → 作業ツリーが
汚れる → 次の `git pull` が「ローカルの変更が失われます」で拒否される、という
連鎖になる。しかも `git pull` の失敗に気づかないまま `npm run ios` まで通って
しまうので、「新しいはずの機能が実機に無い」という形で表に出る (実際に
html5-qrcode の位置がずれていて起きた)。

並びが崩れていないかは、これで確かめられる。

```sh
node -e '"'"'const fs=require("fs");
const keys=[...fs.readFileSync("package-lock.json","utf8")
  .matchAll(/^    "(node_modules\/[^"]+)": \{/gm)].map(m=>m[1]);
const sorted=[...keys].sort((a,b)=>a.localeCompare(b));
console.log(keys.every((k,i)=>k===sorted[i]) ? "並びOK" : "並びが崩れています");'"'"'
```

### 直したのに実機で変わらないとき

Xcode は `public` の中身だけが変わった場合、増分ビルドで見落とすことがある。
アイコンなどネイティブ側の差し替えは反映されるのに、画面の文言やレイアウトだけ
古いまま、という出方をする。

どこで止まっているかは、配った先のファイルを直接見れば分かる。
直したときに足した文字列を探す (例: `4.5rem`)。

```sh
grep -rl "探す文字列" ios/App/App/public/_next/static/chunks/
```

- **出てこない** → 配るところまで届いていない。`npm run ios` をやり直す
- **出てくる** → ファイルは新しい。Xcode が古いものを使っているので、
  Xcode で Product → Clean Build Folder (⌘+Shift+K) してから ▶

`npm run build:native` は書き出しのたびに `out-native/` を作り直すので、
Next 側のキャッシュが原因で古いままになることはない (確認ずみ)。

## 出す前に決めておくこと

- **`appId`** (`capacitor.config.ts`)。いまは `jp.yakuminofarm.kuwalabo`。
  ストアに出したあとに変えると別アプリ扱いになり、入れている人の記録が
  引き継げなくなる。出す前に決めきる
- **Apple Developer Program** 年 $99。iOS を配るのに要る
- **Google Play** 買い切り $25

## エサやりのお知らせ

出し先によって、鳴らし方が根本から違う。

| | ブラウザ版 | アプリ版 |
|---|---|---|
| やり方 | 開いている間だけ30秒ごとに見張る | 先の予定を端末に積んでおく |
| 閉じている間 | 鳴らない | 鳴る |
| 文面を決める時点 | 鳴らす直前 | 積むとき (先に決める) |

アプリ版は、鳴るときにアプリが動いているとは限らない。だから
`planFeedingNotices` (`src/lib/breeding.ts`) で、これから14日ぶんの
「その日に何頭たまっているか」を先に出し、`syncFeedingNotices`
(`src/lib/notify.ts`) で端末に積む。

数えるときは **「今日からあとは一度もエサをあげない」と仮定する**。
実際にあげれば、その記録をつけた時点で積み直すので数は減る。逆にすると
(あげる前提で数えると) あげ忘れた日に鳴らなくなる。鳴りすぎるより、
鳴らないほうが困る。

積み直すきっかけは、記録が変わったとき・設定を変えたとき・アプリに
戻ってきたとき。積んである予定は毎回すべて消してから積み直すので、
古い予定が残って実態と合わない知らせが鳴ることはない。

### 気をつけるところ

Capacitor のプラグインは、どんな名前のプロパティにも応答する作りに
なっている。`then` にも応答してしまうため、`async` 関数からプラグインを
そのまま返すと JS が「まだ解決していない約束」と勘違いして `then()` を
呼び、実装がないと言われて落ちる。`src/lib/notify.ts` では、プラグイン
本体ではなくそれを包んだモジュールのほうを返して避けている。

## 写真の置き場

記録は `localStorage` に置いてある。写真もそこに data URI で埋め込んでいたが、
1枚30〜50KBあるので100枚ほどで上限 (約5MB) に当たっていた。
さらに、エサやりを1件つけるだけでも全部の写真ごと書き直していた。

そこで **写真だけを記録の外に出し、記録は id で参照するだけ** にした。

| | ブラウザ版 | アプリ版 |
|---|---|---|
| 記録 | `localStorage` | `localStorage` |
| 写真 | IndexedDB (blob) | 端末のファイル (`Directory.Data`) |

### 成虫は何枚でも、幼虫は1枚

羽化直後と今、大あごの寄りなど、残しておきたい姿は1枚では足りない。
成虫は `photoIds: string[]` で持ち、**先頭が主な1枚** (一覧・個体カード・
血統書はこれを使う)。上限は6枚 — 1枚あたり大小2つで50KBほどなので、
切らないと1頭に何十枚も入れた人の端末だけが重くなる。

幼虫は1枚のまま。見た目で個体差が分かりにくく、何枚も残す意味が薄い。

写真の持ち方は3代ある。読む側は `src/lib/photoRef.ts` だけを通せば、
どの代の記録でも同じように読める。

| 形 | いつの形 |
|---|---|
| `photoIds: string[]` | いま |
| `photoId: string` | 1枚だけ持っていた頃 |
| `photoUrl: string` | 写真そのものを記録に抱えていた頃 |

### 1枚を大小2つで持つ

| | 長辺 | 使うところ |
|---|---|---|
| `<id>-s` | 320px | 一覧のサムネイル・登録画面のプレビュー |
| `<id>` | 1280px | タップして大きく見るとき |

大きいほうだけにすると、44pxのサムネイルのために1280pxを展開することになり、
50頭並べただけで数百MBのビットマップを抱えて端末が持たない。
小さいほうだけにすると大きく見たときに粗い。だから両方持つ。

移行してきた古い写真は長辺320pxしかないので、大きいほうとして入れてある。
欲しい大きさが無ければもう一方で代えるので、一覧でも詳細でも同じ1枚が出る。

記録そのものは1件200〜400バイト程度なので、写真が抜けた `localStorage` は
当分いっぱいにならない (1000頭でも300KB程度)。SQLite へ移す話は、
容量の面ではもう急がなくてよい。

窓口は `src/lib/photoStore.ts` ひとつで、出し先の違いはこの中に閉じてある。

### 気をつけるところ

**旧データの移行は起動時に1回だけ走る** (`src/lib/photoUpkeep.ts`)。
写真を置き場に書けたものだけ記録を差し替えるので、途中で失敗しても写真は
失われない (次の起動でやり直す)。バックアップから取り込んだ記録も
同じ形なので、同じ道を通る。

**迷子の写真の掃除も起動時だけ。** 登録をやめた写真や、記録を消したあとに
残った写真をここで片付ける。ただし追加画面で「写真を選んだがまだ保存して
いない」状態の写真は、どの記録からも参照されていないので迷子に見える。
復帰のたびに掃除すると、入力中の写真を消してしまう。

**バックアップのファイルの形は変えていない** (`version` は 1 のまま)。
書き出すときに写真を data URI へ戻して埋め込むので、1つのファイルで
完結したままで、古いくわらぼでも読める。

複数枚は **主な1枚を `photoUrl`、2枚目以降を `photoUrls`** に入れる。
`photoUrls` を知らない古いくわらぼでも、1枚は読める形にしてある。

**迷子の掃除は参照を数え上げる。** ここを1枚ぶんしか見ないと、2枚目以降が
どこからも参照されていないように見えて、起動のたびに消える。

## 個体カードの共有

個体の詳細から「この子を共有する」で、写真と要点をまとめた1枚の画像を作って
外へ渡せる。即売会の出品や、譲るときの受け渡しに使う。

| | ブラウザ版 | アプリ版 |
|---|---|---|
| 渡し方 | Web Share API | 端末の共有シート (`@capacitor/share`) |
| 使えないとき | 画像の保存に落とす | — |
| ファイルの置き場 | — | `Directory.Cache` (あとで消えてよい) |

**金額は載せない。** 入手金額と販売価格は人に見せるものではないので、
共有する1枚には入れない (`src/lib/shareCard.ts`)。何が載るかは
`cardRows` を試験から見張っているので、うっかり増やせば試験が落ちる。

### 高さを中身に合わせる

載る項目の数は個体によって変わる (産地や体長が空のこともある)。
縦を1350pxに決め打ちにすると、項目が6つある個体では表が下にはみ出して
羽化日が切れ、逆に項目が1つで写真も無い個体では下半分が空白になる。

そこで表の高さを先に出し、残りを写真に渡して、余ったら縦を詰める。
上限は縦4:5 (SNSで切られにくい形) で、それより縦長にはしない。

管理番号と愛称はどちらも長いことがあるので、見出しの幅を分け合う。
入りきらないぶんは「…」で切る (どちらかが消えることはない)。

### 気をつけるところ

やめたこと (共有シートを閉じた) と、渡せなかったことは区別している。
やめたときに「共有できませんでした」と出すと、失敗したように見えてしまう。
`shareCardImage` は `shared` / `saved` / `cancelled` / `failed` を返し、
画面では `saved` と `failed` のときだけ知らせる。

`@capacitor/share` も他のプラグインと同じ罠 (`then` に応答して落ちる) を
持つので、`src/lib/share.ts` ではモジュールのほうを返している。

## 血統書の書き出し

血統の欄に「血統書を書き出す」がある。本人と3世代ぶん (親・祖父母) を
A5の横1枚にして、共有シートか保存で外へ渡せる。即売会の出品や譲渡のときに、
画面を見せる代わりに渡すためのもの。

出し方は個体カードと同じ道 (`shareCardImage`) を通る。刷っても読めるように
1748×1240 (A5 横を 210dpi ほど) で作っている。

**これは自分の記録を書き写したもので、第三者の証明ではない。** 血統書という
名前は証明書のように見えるので、紙の上にもそう書いてある (`src/lib/pedigreeCert.ts`
の足元の注記)。この一文は消さないこと。

記録に無い先祖は、枠を省かずに点線の空枠で「記録なし」と出す。埋まっている枠だけ
並べると、家系のどこが分かっていないのかが受け取った側に伝わらない。

金額を載せないのは個体カードと同じ。`certRows` を試験から見張っている。

## 管理ラベルの印刷

データの持ち出しの中に「管理ラベルを作る」がある。選んだ成虫・幼虫の管理番号を
A4に等間隔で並べた画像を作り、共有シートから「プリント」へ渡せる。
菌糸ビンや成虫ケースに貼るためのもの。書き写す手間と取り違えが減る。

大 (21面・ケース向け) と小 (40面・ビン向け) の2つ。入りきらないぶんは
次の紙に回り、共有シートには複数のファイルをまとめて渡す
(`shareCardImages`)。

### 決めたこと

**市販のラベル用紙の枠には合わせていない。** A-one などは品番ごとに余白が
ミリ単位で決まっていて、そこに合わせると「その品番以外ではずれる」ものになる。
手元で確かめられないので、普通紙に刷って切る前提の等間隔の面付けにし、
切り取りの目安線を入れてある。

**予定は刷らない。** 次のビン交換の目安のようなものは入れない。紙は貼ったあと
直せないので、予定が変わると嘘になる。最後にビンを替えた日 (起きたこと) だけ。

**貼る先があるものだけ並べる。** 売った個体・飼育を終えた個体・成虫へ引き上げた
幼虫は出さない。貼る先がもう無い。

金額を載せないのは個体カード・血統書と同じ。試験で見張っている。

### QR付きのラベル

「QR付き (24面)」を選ぶと、各ラベルにQRが入る。アプリの成虫・育成の画面に出る
QRボタンから読み取ると、その記録が開く。棚の前でビンを持ったまま記録をつけられる。

**QRに入れるのは記録の id** (`kuwalabo:b:<id>` / `kuwalabo:v:<id>`)。
管理番号は後から書き換えられるし、同じ番号を2頭に付けてしまうこともあるので、
札としては使えない。読み取るのは自分のアプリの中だけなので、URLにする必要はない
(短いほうがQRの目が粗くなって読みやすい)。

**QRは刷る大きさを削れない。** 記録のidを入れると25目になり、まわりの余白を
足して33目。25mm四角に刷って1目0.76mmになる。ここを詰めると 0.5mm を割って
手元のカメラでは読めなくなるので、面を増やしたいときは面の数ではなく
**QRなしの型**を使う (`QR_SIZE` のコメントも参照)。

読み取りは `@capacitor/barcode-scanner`。アプリ版は端末のカメラ画面、
ブラウザ版は画面の中にカメラを出す (中で html5-qrcode を使う)。
読み取り機は大きい (360KBほど) ので、使うときまで読み込みを遅らせている
(最初の読み込みには入らないことを確認ずみ)。

**ブラウザ版では先にカメラを確かめる。** 読み取り機は自前の画面を開くが、
カメラが使えないと白い板が出たまま何も言わずに待ち続ける (許可していない・
カメラが無い端末で起きる)。`src/lib/scan.ts` で先に `getUserMedia` を試し、
駄目なときは自分の言葉で伝えてから諦める。

## 出品リスト

データの持ち出しの中に「出品リストを作る」がある。選んだ成虫をA4の表にして、
即売会の卓に置く一覧を作る。2種類ある。

| | 載るもの | 渡す相手 |
|---|---|---|
| 配布用 | 種類・産地・累代・性別・体長・羽化日 | お客さん |
| 手元用 | 上に加えて **原価** | 自分だけ |

値切られたときに下げてよい線は原価で決まるので、手元用には要る。
**紙の上に「お客さんに渡さないでください」と大きく刷ってある** — 刷ったあとに
取り違えると、仕入れ値を相手に見せることになる。配布用に原価の列が混ざらない
ことは試験で見張っている。

原価は、買ってきた個体は入手金額、自分で羽化させた個体は元の幼虫にかかった額
(引き上げのときに入手金額を写していないので、幼虫まで遡らないと出てこない)。

### 決めたこと

**出品価格の欄は作っていない。** いくらで出すかを前もって記録する習慣があるか
どうか分からないので、値段は手書きできるよう空けてある。当日の値付けは手書きの
ほうが早く、書き換えもきく。

**幼虫はまだ並べられない。** 即売会ではラインごとにまとめて出すことが多く、
1頭ずつの表とは形が違う。

**列の幅は最後の1つを残りから出す。** 全部決め打ちにすると、どれか1つを直した
ときに合計が紙幅とずれ、最後の列が切れたり余ったりする。

## 割り出しカウンター

ブリードラインの「数えながら割り出す」から開く。産卵セットを崩しながら、
出てきた卵と幼虫をその場で押して数える画面。

片手にスプーン、もう片方は土まみれという状況で使うので、**見ないでも押せる
こと**を最優先にしてある。段階ごとの枠いっぱい (高さ76px) が「1つ足す」の的で、
戻すボタンだけ右端に小さく分けた — 同じ大きさにすると数えている途中で押し間違える。

### 段階を分けて数える

卵・初齢・2齢・3齢に分ける。まとめて「20」と数えると、あとから菌糸に入れる
時期を決められない (卵は孵化を待つ、3齢はすぐ大きなビンへ)。

**卵には孵化日を入れない。** 掘り出した日を孵化日にすると、そこから日数を
数える画面がすべてずれる。

### 押したら指に返す

画面を見ずに押すところなので、押せたかどうかが指に返るだけで数え間違いが減る。
`@capacitor/haptics` で、

| | 手ごたえ | ブラウザ版の振動 |
|---|---|---|
| 1つ足す | Light | `[20]` |
| 1つ戻す | Medium (足すときと指で区別できるよう重く) | `[43]` |
| 記録できた | Success | `[35, 65, 21]` |

**0のところで戻しても返さない。** 返すと「戻せた」と思ってしまう。

エサやりのボタン (ホームの1頭ずつ・まとめて、一覧のカード、個体の詳細) にも
同じ手ごたえを入れてある。押すと「あげた」と「取り消し」が入れ替わるところは、
**いまどちらになるかで合図を分ける** (あげる=Light、取り消す=Medium)。

**震えないときの切り分け。** ふだんは失敗を黙って流しているので、
「アプリが呼べていない」のか「端末側で切ってある」のかが分からない。
設定の「振動を試す」だけは結果を返すようにしてあり、

| 出る言葉 | 意味 |
|---|---|
| いま振動を送りました | 端末までは届いている。感じないなら端末の設定か低電力モード |
| この端末では振動を使えませんでした | 届いていない (プラグインが入っていない・振動の仕組みが無い) |

入り切りの設定は作っていない。iOS も Android も OS 側に「システムの触覚」の
設定があり、そこで切れば全部のアプリで止まる。振動の無い端末・切ってある端末では
プラグインが投げるので、`src/lib/haptics.ts` で黙って流している
(ここで await を外すと、失敗が try の外へ抜けて「拾われなかった約束」になる)。

### 途中の数は端末に残す

20分かけて掘っているあいだに画面が消えたり、アプリが後ろへ回されたりする。
数え直しは心が折れるので、押すたびに `localStorage` に残し、開き直したときに
続きから出す (`src/lib/splitCount.ts`)。記録するか「0に戻す」で消える。

### 管理番号は番号の最大から振る

`2026-A-06` のように続きから振る。**件数から出してはいけない** — 途中で1頭
消すと番号が戻り、同じ管理番号が2つできる。従来の「割り出しを記録」は件数から
出していたので、カウンター側は最大値を見るようにしてある。

## 自分で足した品種

設定の「品種ごとの目安」から足す。足した名前は登録画面の品種の選択肢にも
「自分で足した品種」として並ぶ (`src/lib/customSpecies.ts`)。

組み込みの一覧に無い品種を飼っている人は、これまで「その他」を選んで毎回
名前を打つしかなかった。打つたびに表記がぶれると、

- 品種ごとの目安が別々に分かれる (「ニジイロ」と「ニジイロクワガタ」)
- 組める相手の候補から漏れる (同じ種類かどうかは名前で見ているため)

という形で、あとから効いてくる。

### 決めたこと

**名前は前後の空白を落とし、間の空白は1つにまとめる。**「オオクワガタ 」と
「オオクワガタ」が別の品種として並ぶと、目安も候補も割れる。

**組み込み・既出と同じ名前は弾く** (「その品種はもう選べます」)。空白の入れ方が
違うだけの名前も、そろえたあとで見るので同じものとして弾かれる。「その他」は
選択肢の仕組みで使っているので、品種の名前には使えない。

**記録が1件も無くても目安の一覧に並ぶ。** 迎える前に目安だけ決めておけるように
してある (`tuningTargets` は使用中の品種と足した品種を合わせて出す)。

**記録のある品種は一覧から外せない。** 外すと、その記録を直すときに品種が
「その他」へ落ちてしまう。外す入り口は、自分で足した・まだ記録の無いものにだけ
出す。名前を消しても記録側には触らない。

**控えに入れて持ち出せる。取り込みでは足すだけにする** (`mergeAll`)。取り込んだ
記録の品種が選べないままだと、直そうとしたときに困る。ほかの設定は上書きしない
方針なので、ここだけ例外にしてある。

## 畳んで見せる

「使い方」と、各タブの上にある絞り込み・並べ替えのチップを、開け閉めできる形に
した (`Accordion` / `FilterBar`)。どちらも**ふだんは読まないのに、いちばん
目立つ場所を占めていた**もの。

### 閉じていても中身が分かるようにする

見出しだけを並べて畳むと、自分に要るものかを確かめるために結局ぜんぶ開くことに
なり、畳んだ意味がなくなる。閉じているときも1行だけは見せる。

| | 閉じているときに見えるもの |
|---|---|
| 使い方の各章 | 章の題 + その章に何が書いてあるかの1行 (`GuideSection.lead`) |
| 一覧の絞り込み | 「6頭を表示中」+「飼育中 ・ エサまだ / 新しい順」 |

**使い方は最初の1章だけ開けておく。** 全部閉じた状態で出すと、開けるものだと
気づかれないまま閉じられてしまう。畳んだことで、使い方の全長は 6038px から
1629px (画面 7枚ぶん → 2枚ぶん強) になった。

### 絞り込みは「なぜこの件数か」を出す

チップを畳むと画面は静かになるが、そのぶん**効いている条件が見えなくなる**。
気づかないまま「登録したはずの子がいない」と探すことになるので、

- 見出しをそのまま件数にした (「3頭を表示中」)。絞ると数字が動く
- その下に効いている条件を1行で出す
- 条件が1つでも効いていたら、右端に濃い色で数を出す

**絞り込みと並べ方は `/` で分ける。**「飼育中 ・ メス / 大きい順」のように、
件数が変わるものと変わらないものを混ぜない。混ぜると、並べ方を変えただけで
件数が減ったように見える。

**条件の順番は、押した順ではなく選択肢の並び順にする** (`activeLabels`)。
Set は入れた順を覚えているので、そのまま使うと同じ条件でも文が変わる。

### 一覧の中の見出しも畳める

育成タブの「幼虫 / 前蛹・蛹 / 羽化した子」と、成虫タブを種類ごとにまとめた
ときのそれぞれの種類は、見出しを押すとその束だけ伏せられる (`ListGroup`)。
幼虫を見ているあいだ、羽化した子を伏せておくような使い方を想定している。

**こちらは最初から開けておく。** 畳んだ状態で出すと一覧が空に見えるし、その
一覧こそ、その画面に来た目的だから。上の絞り込みとは事情が逆になる。

**畳んでも頭数は見出しに残す。** 伏せた束に何頭いるか分からないと、閉じたことを
忘れて「減った」と思う。

### ホームの節も畳める

今日のエサやり・やることリスト・進行中ライン・大型候補・自己ベストを、
右端の印から畳めるようにした (`FoldableSection`)。

**畳む印は見出しと別の場所に置く。** 見出し自体が「一覧へ移る」「自己ベストを
開く」という役目をすでに持っている。そこに畳む役目まで足すと、押すたびに
どちらが起きるか分からなくなる。見出しはこれまでどおり、右端の印だけが畳む。

**ホームの畳み方だけは覚える。** 一覧の絞り込みと違って、これは「この節は
見ない」という続く好み。毎回開き直させる意味がない。

**畳んでも数は見出しに残す** (「のこり3頭」「2件」「3ライン」)。閉じたことを
忘れて「減った」と思わないように。

**控え (バックアップ) には入れない。** 端末ごとの見た目の好みであって、記録では
ないため。

### 決めたこと

**一覧の絞り込みの開け閉めは覚えない。** タブを移ると絞り込み自体が外れる作り
なので、開き方だけ覚えていても噛み合わない。次に開いたときは、また静かな状態
から始まる。

**記録が1件も無いタブでは帯ごと出さない。** 絞るものが無いのに絞り込みがある
と、最初の1頭を登録する前にひっかかる。

## 管理番号を下書きする

登録画面を開いた時点で、**その人がすでに打った番号の続き**を入れておく
(`src/lib/beetleCode.ts`)。番号の付け方は人それぞれ (25OK-A1 / No.7 /
久留米-3…) なので、こちらから型を決めず、手元の記録から学ぶ。

| どこ | 何を種にするか |
|---|---|
| 成虫を1頭で登録 | 同じ品種で最後に登録した番号 |
| 成虫をペアで登録 | ♂ は同じ品種の続き、♀ は ♂ の続き |
| 幼虫を登録 | 選んだラインの続き (割り出しカウンターと同じ形) |

### 系統と番号を分けて入れる

25OK-A3 の `25OK-A` が**系統**、`3` が**番号** (`src/lib/codeSeries.ts`)。
系統は一度決めるとしばらく変わらないので選ぶだけにして、打つのは番号だけに
する。系統を選び直すと、番号はその系統の続きに入れ替わる。

```
管理番号 *
[ 25OK-A ▾ ] [ 3 ]
25OK-A3 として記録します
```

**記録の中では、これまでどおり1つの文字のまま持つ。** ラベルも QR も CSV も
血統書も管理番号を1つの文字として扱っているので、そこを分けると全部に響く。
分けているのは入力のときだけ。

**選べる系統は、使ったことのあるものから作る。** 登録の手間を増やさないため。
新しく使ったものほど上に出す。設定の「管理系統」で足せるのは、**まだ1頭も
登録していない系統を先に決めておきたいとき**のためで、ふだんは要らない。

**系統の終わりに数字は置けない。**「25」+「3」は「253」になり、読み直すと
系統なしの253番になってしまう。設定で足すときに弾く。

**記号を付けず 1, 2, 3… と振っている人もいる。** 系統が空になるだけなので、
そのまま扱える。選ぶときは「(記号なし)」と出す。

**末尾が数字でない番号は、分けずにそのまま打つ**「オオクワ♂」のような番号は
系統と番号に分けられない。その記録を開いたときは、これまでどおり1つの欄で
出す (「自分で書く」)。分けられないものを無理に分けると、番号が変わってしまう。

**番号は選ぶだけにする。** その系統で**すでに使われている番号は並べない**ので、
同じ管理番号を2つ作ってしまうことがない。1 から「いちばん大きい番号 + 20」
(少なくとも50) まで並べ、埋まっているものを落とす (`numberOptions`)。
**先をどこまで出すかに正解はない** — 少なすぎると飛ばした番号を使えず、多すぎると
選ぶのが大変になる。ここより先を使いたい人は「自分で書く」。途中が抜けているとき (消した子の
番号) はその番号も選べるが、はじめから入っているのは**続きの番号**のほう。
桁は、その系統でいま使っている書き方に合わせる (01 なら 02, 03…)。

**直しに来た本人の番号は、埋まっていても選べる。** 自分の番号が選べないと、
ほかの欄だけ直したいときに番号を変えるはめになる。

**それでも外れる番号のために「自分で書く」を残す。** 選択肢の先にある番号
(137番など) を使いたい人は、こちらで打てる。

**番号が空のあいだは、管理番号ができていない扱いにする。** 系統だけを管理番号に
すると「TD-」のような番号で登録できてしまう。しかもそれは系統と番号に分け直せ
ないので、**系統の欄まで空に見える** (実際にそうなった)。番号を消しているあいだ
だけは、系統を覚えておいて欄に残す。ペアの ♀ も同じで、♂ の番号を打ち直して
いる途中は続きを出しようがないので、前の番号をそのままにしておく。

**重なりは知らせるが、止めない。** 同じ番号がほかの子にあるときは赤で出す。
ただし付け替えの途中ということもあるので、登録そのものは止めない。直している
本人の番号は、重なりに数えない。

### 決めたこと

**同じ品種の続きしか出さない。** 品種ごとに記号を変えている人 (25OK-… /
25PH-…) に別の品種の続きを出すと、気づかずに取り違える。その品種が1頭も
いなければ、下書きしない。

**だから、登録画面は前に登録した品種から始める。** ここを「オオクワガタ」に
固定していたせいで、オオクワガタを飼っていない人には下書きが1つも出て
こなかった (実際に出なかった)。続けて登録するときはたいてい同じ品種なので、
品種を選び直す手間も減る。

**それでも通し番号の人に効く。** `nextCode` は埋まっている番号を飛ばすので、
同じ品種の最後が古くても (No.2 → No.3 は埋まっている)、空いているところまで
進む。

**品種を変えたら引き直す。** 開いたときの下書きのまま品種だけ変えられると、
番号と品種がちぐはぐになる。

**自分で打ったあとは、こちらから書き換えない。** 途中まで打った番号が品種を
変えた拍子に消えるのがいちばん困る。

**下書きだと分かるように、できあがる番号を下に出す** (「25OK-A3 として記録
します」)。黙って入っていると、打ち間違いが残っているように見える。

**幼虫の番号は最大値から出す** (`nextCodeNumber`)。件数から出すと、途中で
1頭消したときに同じ番号が2つできる。

## 累代を選んで決める

自由入力をやめて、区分 (WD / WF / CB / F / 不明) と代数を選ぶ形にした
(`src/lib/generation.ts`, `GenerationField`)。打つのが面倒なうえ、
「CBF2」「cbf2」「CB F2」が別物として並んでしまっていた。

区分を選ぶと、その意味を1行で出す。WF と CB の違いは、はじめての人には
分からない。

| 選ぶもの | 記録される形 |
|---|---|
| WD 野外採集 | `WD` |
| WF 野外の子 + 代数 | `WF1` |
| CB 累代 + 代数 | `CBF1` |
| F 代数のみ + 代数 | `F1` |
| CB 累代 + わからない | `CB` |
| 不明 | (空のまま) |

### 決めたこと

**`CB` と `CBF1` は別ものとして扱う。** お店のラベルには両方ある。CBF1 は
何代目かを数えている表記で、CB だけのときは「飼育品だが何代目かは数えて
いない」という意味で使われる。代数の選択肢に「わからない」を置いて、
ラベルどおり `CB` のまま残せるようにした。

そのため、**`CB` を親にすると子は `CBF1`** になる (`nextGeneration`)。
数え始めがそこだから。

**読めなかった文字は消さない。**「F2 (自己ブリード)」のような書き方も
実際に使われている。型に当てはまらない値は「自分で書く」として、打たれたまま
残す。どの記録を開いても、選び直さないかぎり文字は変わらない。

**CB は `CBF` に揃えて保存する。** 手元の記録も、親から子へ累代を進める計算
(`nextGeneration`) も CBF で書かれている。

**「不明」は空で記録する。** 「不明」という文字を入れると、ラベルにも血統書にも
そのまま刷られてしまう。空欄なら、もともと出ない。

**「自分で書く」を残す。** これまでできていたことを取り上げない。型を増やすより、
逃げ道を1つ用意しておくほうが壊れにくい。

## 産地・血統を呼び出す

その品種で使ったことのある産地を欄の下に並べ、押すだけで入るようにした
(`src/lib/locality.ts`, `LocalityField`)。

迎えるたびに打ち直すと「能勢YG」「能勢YG血統」のように表記がぶれる。ぶれた産地は、
血統書でも出品リストでも**別の産地として並んでしまう**。

### 決めたこと

**品種でしぼる。** 産地の名前は品種ごとに違う。オオクワガタに「パラワン島」が
出てくると、押し間違いを誘う。その品種で使ったことがなければ、何も出さない。

**新しく使ったものほど前に出す。** 同じ産地を続けて迎えることが多い。

**下書きはしない。** 管理番号と違って、産地は前と同じとはかぎらない。勝手に
入れると、違うことに気づかないまま登録してしまう。押したときだけ入る。

**もう一度押すと外せる。** 押し間違えたときに、打ち直さなくて済む。

**打つ欄は残す。** はじめての産地は打つしかないし、「久留米 (○○産)」のように
足したい人もいる。

## 欄の幅は中身に合わせる

体長・日付・番号のように**中身の長さが決まっている欄は、横いっぱいに伸ばさない**
(`.kuwa-input-num` / `.kuwa-input-date`)。数字4桁や日付のために画面の半分を使うと、
空白ばかりの画面になる。

**2列の grid ではなく、折り返す flex に置く。** iOS の日付欄は、幅を指定しても
**固有幅のほうが勝つ**ことがある。grid の列は幅が決まっているので、あふれたぶんが
そのまま右にはみ出す (実際に羽化日がはみ出した)。折り返す行なら、入りきらない
ときは次の行に落ちるだけで、はみ出さない。

**日付欄は端末まかせの見た目を切る** (`appearance: none`)。これで固有幅より
指定した幅が通る。Chromium ではカレンダーの印 (`::-webkit-calendar-picker-indicator`)
は残り、見た目も幅も変わらないことを確かめてある。折り返しのほうは、この指定が
効かない端末に備えた**二重の備え**として残す。

| 欄 | 幅 |
|---|---|
| 体長・頭数 | 6rem |
| 日付 | 10rem |
| 管理番号の番号 | 6rem |

**「だいたい」は日付欄のすぐ隣に置く。** 見出しの行の右端に置いていたが、
日付欄を細くしたぶん離れてしまい、どの欄にかかる操作なのか分からなくなった。
幅は、日付とチップと隣の欄が1行に収まるところから決めている。

幅430・390・375・320px で測って、どれもシートの中に横スクロールが出ないことを
確かめてある。390px までは「体長 + 羽化日 + だいたい」「入手日 + だいたい +
後食済み」がそれぞれ1行に収まり、375px からは折り返す。

## 端末でしか確かめられないこと

ここまでの確認は、計算の部分の自動テストと、ブラウザ版が今までどおり
動くことまで。次は実機で見るしかない。

- 通知の許可を求める画面が出るか
